# SEO & AI discoverability

How Our Family Socials is made findable in Google and Bing, and quotable by AI
answer engines (ChatGPT, Claude, Perplexity, Gemini, Copilot, Grok).

Canonical host: **https://www.ourfamilysocials.com** — `ourfamilysocials.com`
307-redirects to `www`, so every canonical, `og:url`, sitemap entry and
IndexNow URL uses the `www` form. Change `SITE_ORIGIN` in
`frontend/src/content/site.js` if that ever flips.

---

## What was wrong

Crawlers were getting an 8-word page. The site is a Vite + React SPA that ships
an empty `<div id="root">`, and while a `scripts/prerender.js` existed, two
things stopped it mattering:

1. `vercel.json` rewrote **every** path to `/index.html`, so the files it wrote
   to `dist/<route>/index.html` were never served.
2. The deployed build did not run it at all — the live home page still carried
   `index.html`'s original meta description, not the prerendered one.

On top of that, `/llms-full.txt` returned the SPA shell with a 200 (worse than a
404), the canonical pointed at the non-`www` host that redirects away, and
`Compare.module.css` referenced CSS variables that do not exist
(`--background`, `--card-background`, `--border`), so the comparison pages
rendered without their cards or borders.

## What is in place now

### 1. Build-time prerender (not user-agent sniffing)

`frontend/scripts/prerender.mjs` runs after `vite build` and writes one static
HTML file per public page into `dist/`:

| Route | File |
|---|---|
| `/` | `dist/index.html` |
| `/features` | `dist/features.html` |
| `/pricing` | `dist/pricing.html` |
| `/faq` | `dist/faq.html` |
| `/about` | `dist/about.html` |
| `/alternatives` | `dist/alternatives.html` |
| `/compare/facebook-groups` | `dist/compare/facebook-groups.html` |
| `/compare/tinybeans` | `dist/compare/tinybeans.html` |
| `/compare/familyalbum` | `dist/compare/familyalbum.html` |
| `/compare/private-instagram` | `dist/compare/private-instagram.html` |
| `/compare/how-to-share-photos-privately` | `dist/compare/how-to-share-photos-privately.html` |

Each file carries the full page text, a unique `<title>`, a meta description, an
absolute self-referencing canonical, Open Graph + Twitter tags, `lang="en"` and
a JSON-LD `@graph`. The same HTML is served to humans and bots — there is no
user-agent branching anywhere, so no cloaking risk.

`frontend/index.html` contains `<!-- SEO:START -->` / `<!-- SEO:END -->` and
`<!-- SEO:BODY -->` markers. The prerenderer swaps those blocks per page. **If
you remove the markers the build fails loudly** rather than silently shipping an
empty shell.

### 2. One source of truth for content

`frontend/src/content/` holds the page content as plain data:

- `marketing.js` — every public page as `{ path, title, description, h1, lede, blocks }`
- `faqData.js` — the FAQ questions, also imported by `src/pages/FAQ.jsx`
- `renderStatic.js` — renders those blocks to HTML, to plain text and to JSON-LD
- `inline.js` — the tiny `**bold**` / `[label](url)` markup shared by both renderers
- `site.js` — canonical origin, published prices, IndexNow key

`src/components/MarketingPage.jsx` renders the **same** data in React. That is
why the visible page, the prerendered HTML, `llms-full.txt` and the structured
data can never drift apart.

### 3. Routing

`frontend/vercel.json`:

- `buildCommand: "npm run build"` — pins the build so the prerender always runs,
  overriding whatever the Vercel dashboard has set. **This is the fix for the
  "prerender never ran in production" problem; do not remove it.**
- `cleanUrls: true` + an explicit rewrite per marketing route, so `/faq` serves
  `faq.html`.
- A final `/(.*) -> /index.html` catch-all, so every app route (`/feed`,
  `/event/:id`, `/profile/:username`, `/admin/*`, …) keeps working exactly as
  before. Vercel applies rewrites *after* the filesystem check, so real files
  such as `/robots.txt` and `/llms.txt` are served directly.
- `headers` pinning `text/plain` on the `.txt` files and `application/xml` on
  the sitemap.

### 4. robots.txt, sitemap.xml, llms.txt, llms-full.txt

All generated by `frontend/scripts/generate-seo-files.mjs` into
`frontend/public/` **and committed**, so they exist even if a deploy skips the
postbuild step. Regenerate with `npm run seo:files` (it also runs automatically
as `prebuild`).

- `robots.txt` — `Allow: /` for everyone plus an explicit group for Googlebot,
  Google-Extended, bingbot, OAI-SearchBot, ChatGPT-User, GPTBot,
  Claude-SearchBot, Claude-User, ClaudeBot, PerplexityBot, Perplexity-User,
  Applebot, Applebot-Extended, DuckAssistBot, meta-externalagent and CCBot. Only
  app/admin/API routes are disallowed. Absolute `Sitemap:` line.
- `sitemap.xml` — the 11 prerendered canonical URLs with `lastmod`.
  `/privacy`, `/terms`, `/contact` and `/blog` are deliberately **not** in it:
  they are public React routes with no prerendered text, so listing them would
  put soft-empty pages in front of crawlers. They stay reachable via the footer.
- `llms.txt` — short and factual: what it is, who it is for, what it costs, what
  is *not* available yet, and links to every public page.
- `llms-full.txt` — the complete plain text of all 11 pages, generated from the
  same content module. Per the research, llms.txt files show no measured
  citation benefit yet, so this is kept cheap and accurate rather than elaborate.

### 5. Structured data

A single JSON-LD `@graph` per page: `Organization`, `WebSite`, `WebPage`,
`WebApplication` (on `/`, `/features`, `/pricing`), `BreadcrumbList` on
subpages, `FAQPage` on `/faq`, and `Article` on the comparison pages and
`/alternatives`.

Deliberately **absent**:

- **No `aggregateRating` or `review`** — there are no published reviews, and
  inventing them risks a manual action.
- **No `sameAs`** — the footer's social icons are `#twitter` / `#instagram` /
  `#facebook` placeholders, so there are no real profile URLs to point at. Add
  them to `ORGANIZATION` in `renderStatic.js` once the accounts exist.
- **No `MobileApplication`** — there is no App Store or Google Play listing.

`offers` mirror the prices published on `/pricing` exactly ($0 free, $108/year,
$12/month, $294 lifetime).

### 6. Soft 404s and the service worker

- Vercel's SPA catch-all means an unknown path still returns 200 with
  `index.html`. `src/pages/NotFound.jsx` is wired to `<Route path="*">` so those
  paths render a real "page not found" screen and add
  `<meta name="robots" content="noindex, follow">`. Googlebot renders
  JavaScript, so it sees the noindex; non-rendering crawlers only ever reach the
  11 prerendered pages, which are all real.
- `vite.config.js` sets `workbox.navigateFallbackDenylist` for the marketing
  routes. Without it an installed PWA's service worker would answer `/faq` and
  `/pricing` from the cached `index.html`, so those pages would show the home
  page's `<title>` and meta description to returning visitors.

### 7. Performance

- Hero image on the landing page is `fetchpriority="high"`; the other 18 images
  are `loading="lazy" decoding="async"`.
- `/images/photobooks.png` carries real `width`/`height` (1344×768). The
  remote Unsplash images are sized by CSS (`object-fit: cover` in fixed-height
  containers), so adding guessed intrinsic dimensions would *cause* layout shift
  rather than prevent it.
- The unused Cloudinary upload widget `<script>` is now `defer`red instead of
  blocking first paint. Nothing in `src/` references the `cloudinary` global —
  it can probably be deleted outright, but deferring is the safe step.
- The prerendered HTML adds no JavaScript and about 1 kB of inline CSS.

## Owner steps (these need you to sign in — they were not done here)

### Google Search Console

1. Go to https://search.google.com/search-console and add a property.
2. Prefer the **Domain** property (`ourfamilysocials.com`) and verify with the
   DNS TXT record it gives you — that covers `www`, non-`www`, http and https in
   one go.
3. If you would rather use the URL-prefix property, pick
   `https://www.ourfamilysocials.com/` (the host that actually returns 200) and
   verify with the HTML meta tag. In that case add the tag to
   `frontend/index.html` **below** the `<!-- SEO:END -->` marker, or it will be
   overwritten by the prerenderer on every build.
4. Submit `https://www.ourfamilysocials.com/sitemap.xml`.
5. Check **Settings → Search generative AI** is left on *include*, and watch the
   Generative AI performance report.

### Bing Webmaster Tools

1. Go to https://www.bing.com/webmasters and choose **Import from Google Search
   Console** — that reuses the verification you just did.
2. Otherwise add `https://www.ourfamilysocials.com/` and verify by meta tag
   (same placement rule as above) or DNS.
3. Submit the same sitemap. Bing also feeds Copilot and DuckDuckGo.

**No placeholder verification tokens have been committed.** Do not commit a
made-up token — an invalid one is worse than none.

### IndexNow

The key file is already live at
`https://www.ourfamilysocials.com/8e5db8617ace1a3455a41ec1662533fd.txt` after
the next deploy (source: `frontend/public/`, key constant in
`frontend/src/content/site.js`).

```bash
cd frontend
npm run seo:indexnow -- --dry-run   # prints the payload, sends nothing
npm run seo:indexnow                # submits to https://api.indexnow.org/indexnow
```

Run it **after** a deploy that includes the key file, otherwise IndexNow
returns 403. It submits all 11 canonical URLs plus the sitemap, which covers
Bing, Yandex, Seznam and Naver.

## Verifying

```bash
cd frontend
npm ci
npm run build        # runs seo:files -> vite build -> prerender
npm run seo:check    # asserts the built output is crawlable
```

`npm run seo:check` fails the command if any public page is missing a title, a
meta description, a correct absolute canonical, exactly one `<h1>`, `lang`,
OG/Twitter tags, parseable JSON-LD, or more than 300 words of
JavaScript-free text — and it checks robots.txt, the sitemap, both llms files
and the IndexNow key file.

To look at the built site exactly as Vercel will route it:

```bash
node scripts/serve-dist.mjs 4173
curl -s http://localhost:4173/faq | grep -c '<h1>'
```

## Adding a new marketing page

1. Add a page object to `PAGES` in `frontend/src/content/marketing.js`:
   `{ path, title, description, h1, lede, breadcrumb, updated, blocks }`.
   Block types: `h2`, `h3`, `p`, `ul`, `ol`, `faq`, `compare`, `cta`.
   Inline markup: `**bold**` and `[label](/path)`.
2. Create the React route component (4 lines — copy
   `frontend/src/pages/Features.jsx`) and register it in `src/App.jsx` inside
   the `<Layout>` route group.
3. Add a rewrite for it in `frontend/vercel.json`, **above** the `/(.*)`
   catch-all.
4. Link to it from `src/components/Footer.jsx` and the landing footer in
   `src/pages/Landing.jsx`.
5. `npm run build && npm run seo:check`.

The sitemap, `llms.txt` and `llms-full.txt` pick the page up automatically.

## Content rules for these pages

- **Truthful only.** Every claim must be traceable to this repo or to the live
  site. No invented users, testimonials, stats, ratings, awards or prices.
- **Competitor facts** must be general, well known, hedged ("per their website,
  as of October 2026"), linked to the competitor's own site, and must include
  where the competitor is *better*. If you are not sure of a detail, leave it
  out — see the Cluster paragraph on `/compare/private-instagram` for the
  pattern.
- **Date the comparison pages.** `LAST_UPDATED` and `LAST_UPDATED_ISO` in
  `marketing.js` drive the visible "Last updated" line, the sitemap `lastmod`
  and JSON-LD `dateModified`. Bump both when the content actually changes.

### Known inconsistency worth fixing (product, not SEO)

`/pricing` describes the free plan as "**View-only** — cannot create events",
but `backend/app/api/events.py`, the landing hero and the FAQ all say free
accounts can publish up to **5 events**. These pages repeat the published FAQ
wording verbatim and otherwise describe the free plan only as "$0/forever, view,
like, comment, follow, maps and timeline" to avoid asserting either version.
Pick one and make the pricing page, the landing hero, the FAQ and the backend
agree.
