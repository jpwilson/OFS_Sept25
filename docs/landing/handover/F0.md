## The two things that must not go wrong

**1. The classic variant is today's site.** OFS has real users and production builds as `classic`. After your change, a classic build must serve every route as it does now: `/` shows the existing `Landing`, `/login` and `/feed` work, the prerendered marketing pages are unchanged. Prove it. Before you edit anything, run `npm run build` and copy `dist/` to a scratch folder as the baseline (you may not change git state, so no stash or worktree). After your work, run `VITE_LANDING=classic npm run build` and compare the two: the prerendered html files other than `index.html` must be byte-identical apart from asset hash names, and `index.html` may differ only by the boot script and asset names. Report the diff summary.

**2. The story variant must not strand anyone.** If the landing chunk fails to load or throws, the visitor still has the static page (it is real HTML) and working links. A signed-in user who lands on `/` goes to the app and `/feed` as today. `/login`, `/feed`, `/event/x` first paint must show no landing markup.

## Build these, in this order

1. **Baseline.** `cd frontend && npm ci && npm run build`; copy `dist/` aside. Note the main JS and CSS byte sizes.

2. **Variant.** `landing.config.json`, `scripts/landing/variant.mjs` (exports `resolveVariant()`), wired into `vite.config.js` as `define: { __LANDING_VARIANT__ }` and into the html (replace a placeholder in the inline boot script through a tiny `transformIndexHtml` plugin). `VITE_LANDING=classic|story` overrides.

3. **Bootstrap.** Move today's `src/main.jsx` body to `src/boot-app.jsx` unchanged. New `main.jsx` reads `document.documentElement.dataset.boot` and dynamically imports `./landing/entry-client.jsx` or `./boot-app.jsx`. The inline script in `index.html` (after `<!-- SEO:END -->`, before any stylesheet) sets `data-boot` per SPEC; wrap storage access in try/catch and treat a storage error as "no session". In the classic variant it always sets `app`. Add a `?landing=legacy` escape that forces `app`... and in `App.jsx`'s `RootRedirect`, story variant with no user renders the lazy `landing/Page.jsx` unless `?landing=legacy`, in which case the existing `Landing`. That is the only edit to `App.jsx`. Keep the `<!-- SEO:START -->`, `<!-- SEO:END -->` and `<!-- SEO:BODY -->` markers.

4. **Scroll and maths.** Port `scroll.ts` and `math.ts` to `src/landing/lib/` as JavaScript with JSDoc, same names, plus the changes in SPEC's contracts (`startScroll()` returns a stop function and is reference-counted because the app runs under StrictMode; restore `history.scrollRestoration` and destroy Lenis on last stop; `prefersReducedMotion()`). Add `lenis` to `package.json`.

5. **Styles.** `styles/tokens.css` (tokens and washes on `.ofsl` and `[data-wash]` inside it), `styles/base.css` (the landing's own reset, font, link and focus rules, all prefixed `.ofsl`; the `html.ofsl-on` page rules; `html[data-boot="app"] #root > [data-ofsl] { display: none }`), `styles/fonts.css`. Fonts: download the Latin woff2 files for Bricolage Grotesque (variable, with the `wdth` and `opsz` axes), Literata (variable) and DM Mono 500 from the `@fontsource-variable/*` and `@fontsource/dm-mono` npm packages (install them as devDependencies in a scratch folder, or `npm pack`, and copy the files; do not add them to `frontend/package.json`) into `public/landing/fonts/` with stable names, `font-display: swap`, and a `size-adjust`ed system fallback so the swap does not jump. Confirm in a screenshot that `wdth` 86 and 75 really render narrower than 100.

6. **Primitives** in `src/landing/ui/`, each a `.jsx` with a `.module.css`, as listed in SPEC's contracts. Port from the reference where one exists (`Button`, `Label`, `Cutout`, `GhostWord`, `Readout`, `Reveal`, `Section`, `Stage`, `Stub`) and restyle to SPEC's look (keylines, hard shadows, stickers). New ones:
   - `Head`: renders `before`, a `Sticker` around `mark`, `after`; `as` picks the tag.
   - `Sticker`: the white tilted label.
   - `Shot`: a real-interface capture from the manifest (`kind: 'ui'`) in a keylined frame with the mandatory caption `Real interface. Sample family.` (pass `caption={false}` only when several shots share one caption).
   - `Print`: a photo from the manifest as a white-bordered print with an optional caption and tilt.
   - `Device`: a CSS phone frame (keyline, radius, notch) that holds a `Shot`; no generated phone image.
   - `AudienceSwitch`: a native radio group (`name`, five options in SPEC's order) styled as a segmented control with a sliding thumb; arrow keys work natively; it must work before hydration (uncontrolled default `Followers`, state readable in CSS through `:has(input:checked)` on a wrapper that the consumer can target with `data-aud`); `onChange` after hydration; `track('landing_audience', {value})`.
   - `Icon`: a small drawn SVG set (arrow, play, pin, lock, people, heart, close, check, plus).
   All must be server-renderable (no browser globals in render).

7. **Manifest reader** `art/manifest.js` over `art/manifest.json` (the ART builder writes the json and may already have; if the file is missing create `{}`): `art`, `maybeArt`, `hasArt`. `Cutout`, `Print` and `Shot` render a neutral labelled placeholder box with the right aspect when an id is missing, and log once.

8. **Content.** `content/facts.js` from SPEC's facts table (`FACTS` with `value` and `src`, `fact(id)`, `PRICES` imported from `src/content/site.js`), `content/cast.js` (the thirteen people, who follows, close family, the Run club group, with derived counts), `content/routes.js`, `content/seo.js` (see step 10). `scripts/landing/check-facts.mjs`: fails if any `content/*.js` file other than `facts.js` and `cast.js` contains a digit inside a string literal that is not produced by `fact()` (allow digits inside ids, hex colours, and the fixed lines `STORY 01` to `STORY 04`).

9. **The page.** `Page.jsx` renders `<div className="ofsl" data-ofsl>` with every section in SPEC's order, imported from the package indexes. Each package index starts as stubs: a labelled band (`<Stub name="Film" />`) with the right `id`; make the Film stub 300svh tall with a sticky child so scrolling can be tested. `Page` starts the scroll engine in an effect, adds and removes `html.ofsl-on`, maps the two old hashes, and calls `initAnalytics()`. `entry-client.jsx` hydrates when `#root` has landing markup and otherwise renders. `dev/Only.jsx`: in dev, `/?only=film|explain|proof|close|ui` mounts just that package (and `ui` shows every primitive on every wash), so a half-written sibling cannot break another builder's view.

10. **Server render and prerender.** `entry-server.jsx` exports `render()` returning the html string of `<Page />`. `vite.landing-ssr.config.js` builds it (react plugin, `ssr: true`, CSS Modules class names must hash the same as the client build; verify by grepping a module class from the client CSS in the server output). `package.json` build becomes: prebuild, `vite build`, the server build, `prerender.mjs`. In `prerender.mjs`, for `/` in the story variant only, put the rendered html in `#root`, and add to the head: the landing stylesheet (find it in Vite's manifest) so first paint is styled, `modulepreload` for the landing entry chunk, and font preloads for the two faces the hero uses. App routes share this `index.html`, so decide how they avoid blocking on the landing stylesheet and say what you chose (a script-written link when `data-boot="landing"` plus a `<noscript>` link is acceptable). `content/seo.js` builds the home page's `blocks` for `llms-full.txt` and JSON-LD from the packages' content files, so `marketing.js`'s `home` keeps its title and description and gets the new h1 and lede; in the classic variant `home` is untouched. `npm run seo:check` must pass in both variants; relax `check-seo.mjs:91` only as far as accepting attributes on the h1. Fail the build if the story `index.html` does not contain exactly one `<h1`.

11. **Service worker and headers.** `workbox.globIgnores: ['landing/**']` so images and fonts are never precached; landing JS and CSS chunks stay precached so a cached `index.html` always finds its own chunks. `vercel.json`: one immutable cache header for `/landing/(.*)`. Verify `dist/sw.js` lists nothing under `landing/`.

12. **Analytics.** `lib/analytics.js`: after `requestIdleCallback` (fallback timeout), dynamically import `posthog-js` and `@vercel/analytics` (`inject()`), initialise PostHog with exactly the options in `src/context/PostHogContext.jsx` (move those options to a small shared module both import, changing nothing about them), register `{ app: 'ofs' }`, send one `$pageview` with a `path` property, and expose `track()` that queues until ready. No calls on the server.

13. **Screenshots.** Port `otherwise/scripts/shots.mjs` to `scripts/landing/shots.mjs` with flags `--url`, `--out`, `--selector`, `--steps`, `--from`, `--to`, `--phone`, `--w`, `--h`, `--reduced`, `--nojs`, `--click <selector>`, `--press <key>`; it writes numbered JPEGs plus one contact `sheet.jpg`, and prints console errors and whether the page scrolls sideways. Output goes under `frontend/shots/` (add it to `.gitignore`).
